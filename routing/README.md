# Research routing
Run `python scripts/route.py "<actual task>"` from the library, or use its absolute script path from another project. It selects up to three matching task domains and three relevant categories, distributing catalogue leads across those categories. The first category is each route's primary expertise; remaining categories are optional supporting expertise.

Coverage includes product/UI/UX, onboarding, pricing/monetisation, landing pages, components/design systems, accessibility, messaging, analytics/experimentation, competitive research and retention, plus existing email, advertising, navigation, social, presentation and performance routes. Exact small edits return a lightweight path without obligatory external research. Unknown tasks return `needs-context` with no invented landing-page default.

This is a deterministic keyword aid, not semantic intent classification. It does not reliably understand negation, implied goals or arbitrary languages. Scores count keyword signals, ties use configuration order, and all matches are returned for contextual review. Agents must use the target project's real users and constraints to accept or override suggestions. The catalogue is not a whitelist: discover relevant original product pages and authoritative research beyond it. Vendor blogs, galleries, public standards and actual outcome studies have different evidentiary value. Verify exact live pages; never equate a reachable homepage with an inspected example or proven conversion.

# Research protocol

## Intake
Identify target users, problem, product stage, desired behavior, baseline, constraints, stack, brand and accessibility requirements. Mark unknowns explicitly.

## Source selection
Select relevant source categories through the router. Inspect original examples rather than relying on catalogue descriptions. For major redesigns, review three independent examples where feasible; disclose shortfalls and selection bias.

## Evidence capture
For each example record exact deep link, UTC access date, page type, directly observed design, mobile coverage, interactive behavior, accessibility concerns, restrictions and confidence. If only a gallery thumbnail is visible, record that limitation.

## Synthesis
Separate observed facts from inference, source claims, published research and product-specific outcomes. Seek counterexamples. Do not assume gallery inclusion implies successful conversion.

## Recommendation
Provide 2-3 original options with rationale, trade-offs, effort, risks and measurement hypotheses. No-change is valid when evidence is weak.

## Implementation
Review current code and existing design system. Test responsive layout, keyboard focus, semantics, labels, errors, loading states and performance where practical. Report commands actually executed.

## Learning
Store dated findings. Promote to patterns only with corroboration. Revisit stale sources before consequential decisions.
